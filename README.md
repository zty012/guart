# GUART · Serial Studio

使用 **MyGo 原生 UI + MujicaUI** 构建的 Go 串口工具。不使用 WebView、HTML 或 JavaScript，无需 CGO。

## 运行

需要 Go 1.27.1 或更高版本。

```powershell
go run .
```

Windows GUI 构建（不附带控制台窗口）：

使用项目已配置的 MyGo CLI：`go tool mygo dev`、`go tool mygo build`。

## 功能

- 枚举和刷新系统串口；可手动输入 `COM3`、`/dev/ttyUSB0` 等端口名，按 Enter 确认。
- 可选自动连接新出现的串口：每秒检测，沿用当前参数，不抢占已有连接。
- 始终开启的被动 MCU 推断：右侧常驻面板显示型号 / 系列、厂商、内核、线索等级及匹配依据；结合 RX 和原生 USB 元数据，不发送探测命令。
- 首次发送后自动比对原始回传数据，提示疑似物理回环；原生 USB CDC 串口额外显示 USB 信息，USB 转串口桥完全按普通串口处理。
- 自定义波特率、5–8 数据位、五种校验、1 / 1.5 / 2 停止位；打开端口时设置 DTR / RTS。
- 异步串口收发；RX 左对齐、TX 右对齐，显示毫秒时间、记录 ID、字节数和换行符类型。
- UTF-8 消息用 Terminal 渲染 ANSI 颜色与样式，样式跨气泡延续；多行消息完整展开，由外层消息列表统一滚动。
- 可逆 RX 显示分组：空闲间隔（默认 10 ms）、LF / CRLF、同一毫秒、原始读取；合并后仍可追溯每次读取的边界与时间。
- UTF-8 / HEX 显示与发送，独立配置无行尾 / LF / CR / CRLF。HEX 使用完整两位字节，不接受 `0x` 前缀。
- 单次发送与循环发送（50–3600000 ms）；Ctrl+Enter 发送，Enter 换行。
- 文本 / 空格分隔 HEX 搜索，方向筛选，暂停显示（继续接收），自动跟随与返回最新消息。
- 原始字节检视器默认隐藏：偏移、HEX、ASCII 对照；键盘选择、Shift 多选、Ctrl+C 复制选中字节，以及复制完整 HEX。
- CSV 日志导出：时间、方向、字节数、完整 HEX、可读文本与演示标记；通过系统保存对话框选择路径。
- 默认跟随系统浅色 / 深色外观，可在右上角“外观模式”中手动选择浅色、深色或恢复跟随系统；支持可拖动侧栏、小窗口独立滚动。
- 明确标识的虚拟演示设备，不打开真实端口；`AT` 返回 `OK`，`HELP` / `INFO` 返回信息，其他数据原样回环。

## 使用方式

1. 选择或输入串口，配置参数，点击「连接串口」。连接期间配置锁定；先断开再修改。
2. 输入文本或切换到 HEX，选择行尾，点击「发送」。快速命令按钮只填入内容，不会擅自发送。
3. 点击某条消息的「检视字节」，使用 HexViewer 查看完整数据。右上角「导出日志」导出所有保留记录，不受搜索和暂停显示影响。
4. 没有硬件时点击「启动演示」测试整个读写流程。演示记录和导出数据均标记 DEMO。

连接校验、连接失败、收发和导出错误统一记录在 MessageList，不再额外显示重复的顶部错误横幅。发送输入校验仍在发送框提示；后台端口检测故障仍在开关和状态栏显示。

## 检查更新

标题栏右侧「检查更新」打开简体中文原生更新窗口，显示检查结果、新版本发布说明，并提供下载、安装和重启操作；检查过程中再次点击会将已有更新窗口置前，不会重复启动检查。使用 MyGo 原生 updater 插件，不需要 WebView。

- 更新源和签名公钥沿用 `mygo.json` 中的配置。正式更新需使用启用更新的 MyGo 发布构建，并发布配套的签名更新产物。
- 保留插件默认的每日后台检查；发现新版本时提示用户，不默认静默安装。跳过版本、稍后提醒和自动下载偏好由插件保存。
- `go run .` 等不能自更新的开发构建仍可点击按钮，窗口会解释无法更新的原因；完整下载、签名校验和安装流程需使用发布构建验证。

## ANSI 与多行预览

- UTF-8 视图采用 MujicaUI `code.Terminal`，支持组件内置的 SGR 前景 / 背景色（含 256 色和真彩色）、粗体、暗色、斜体、下划线、反色和删除线。LF 按串口日志习惯从下一行第 0 列开始，CR、退格、制表和常用光标 / 清屏序列在当前气泡内处理。
- ANSI 样式按接收流延续，不在新气泡开始时重置。后续 SGR 只覆盖指定属性；例如改前景色不会清除粗体，`ESC[0m` 才全部复位。RX / TX 分别保存样式，错误与系统消息不继承设备样式。
- 支持转义序列和 UTF-8 字符跨 Read / 气泡；完整字符在收齐时显示。筛选、暂停、重新分组、切换 HEX 和滚动虚拟列表不改变流状态。日志淘汰及清空显示不清除当前连接的样式，新连接才重新初始化。
- 每个气泡显示完整消息，不按字节截断。Terminal 按实际布局列数重新排版后完整展开，高度包含自动折行，没有 12 行上限或内部滚动；鼠标滚轮交给外层 MessageList。窗口或侧栏宽度改变后重新排版，不通过裁剪旧网格适配。消息不受组件默认 1000 行缓冲限制。鼠标选择后，Windows / Linux 使用 Ctrl+Shift+C，macOS 使用 Cmd+C 复制，不额外显示操作提示。预览输入不会发送到设备，发送仍通过发送框。
- 字节数右侧标记当前显示消息原始字节中的换行符：`CRLF`、`LF`、`CR`、`无换行`；混用时列出实际类型，例如 `混合 CRLF/LF`。CRLF 作为一组识别，不重复统计成 CR 和 LF。分组模式下检查整组数据；自动折行不算原始换行符。
- 气泡之间只延续样式及尚未收齐的序列 / 字符，不延续光标或屏幕内容；后续清屏不会擦掉历史气泡。OSC 标题 / 链接等控制字符串被忽略，不执行外部操作。不是完整的终端仿真，不支持备用屏幕；组件目前不支持宽字符占两格。
- HEX、检视器与 CSV 始终保留原始 ANSI 字节；CSV 文本列仍用可见转义表示控制字符，不把终端画面当作原始数据。搜索同时支持去掉 ANSI 后的文字、原始可读文本和 HEX。

## 自动连接新串口

串口选择框下方的「自动连接新出现的串口」开关默认关闭。开启后每秒后台枚举一次串口，首次成功枚举只记录现有设备，不立即打开它们；随后检测到新出现的端口，且当前没有连接或正在连接的任务时，才沿用当前波特率、数据位、校验位、停止位、DTR / RTS 自动连接。

- 已有串口请手动连接，或在开启检测后拔出再插入。枚举失败不会被当作设备拔出，检测错误会显示在开关下方及状态栏。
- 已连接真实端口、正在连接或使用演示时，不切换端口；这期间新出现的端口也不会排队等待以后连接。
- 同时出现多个端口时，优先连接当前选择的端口（如果它也在新端口中），否则按端口名排序选择第一个；不会自动遍历其他端口。
- 每次出现只尝试一次，连接失败会显示错误，不持续重试；再次检测到拔出、重新插入后才再次尝试。检测到当前真实串口移除时，会释放会话并停止循环发送，之后重新插入可触发自动连接。
- 关闭开关停止检测，并取消尚未完成的自动连接；不会断开已建立的连接，也不会取消手动发起的连接。手动断开后，不会立即重新打开仍然存在的端口。
- 基于端口名而非设备唯一标识识别新增；不能保证重新连接的是同一台物理设备。轮询可能漏掉小于一秒的拔插过程，检测延迟也受系统和驱动影响。此开关和其他设备参数一样，不跨应用重启保存。

## 接收分组与调试

串口提供的是字节流，操作系统的一次 `Read` 并不等于设备的一条消息。比如 `hello\r\n` 可能被读取成 `h`、`ello\r`、`\n`。工作台搜索栏下方的「RX 分组」提供四种显示方式，可以在接收过程中切换，已有保留记录也会重新分组：

| 模式             | 行为与适用场景                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 空闲间隔（默认） | 连续 RX 的相邻读取完成时间差小于阈值时，显示为同一条；可选 1 / 5 / 10 / 20 / 50 / 100 ms，默认 10 ms。适合普通设备调试和二进制数据的阅读。 |
| 按行 LF / CRLF   | 以 LF 结束一条，保留原有 CR / LF 字节；支持 CRLF 跨读取以及一次读取多行。适合 AT 指令、文本日志；单独 CR 不作为结束符。                    |
| 同一毫秒         | 将读取完成时间落在同一个毫秒区间的连续 RX 合并。可解决同毫秒碎片，但跨毫秒边界仍可能拆开同一条设备消息。                                   |
| 原始读取         | 每次 `Read` 单独显示，保留驱动分块，便于分析时序和对照设备行为。                                                                           |

- 分组只改变显示，**不修改原始日志、字节计数或 CSV 导出**。搜索作用于分组后的完整数据；选择消息后的 HexViewer 和「复制 HEX」也包含整组字节。
- 分组数据到达即显示，后续分块会追加到同一条显示消息，不等待凑齐才显示。按行模式未收到 LF 时标注未结束；不会因为缺少换行而隐藏尾部数据。
- 消息时间戳为首个分块的读取完成时间；合并消息另显示读取次数、末次时间和跨度。检视器的「原始分块」列出每个 Read 的微秒显示时间、原始记录 ID、原始偏移、组内偏移和长度，并预览最多 64 字节 HEX；完整原始数据仍在 HEX 视图和 CSV 中。
- 时间是应用从驱动读到数据的时间，**不是串口线上逐字节到达的硬件时间戳**。USB 缓冲和系统调度会影响间隔，显示的微秒位数不代表硬件精度。
- 不跨 TX / SYS / ERR 记录合并，保持采集事件顺序。空闲间隔模式每组时间跨度小于 250 ms，所有合并模式每组最多 64 KiB，防止连续流形成无限增长的单条消息；触及字节上限会注明。按行模式遇到其他方向记录时也会中断当前分组。
- 暂停显示会冻结当时已收到的字节，而不只是冻结条目数量；后台继续接收，恢复时再按当前设置分组。日志容量淘汰仍然有效。
- 普通调试先用默认 10 ms；文本设备优先选按行模式。需要分析精确边界时切回原始读取。对于 Modbus、自定义长度/校验协议，应使用协议专用分帧，不能把时间分组当作协议帧。

循环发送启动时冻结当前内容、格式、行尾和间隔；停止后可修改。停止循环不会撤销已经进入驱动或发送队列的数据。断连或关闭窗口会取消循环、废弃待处理连接和旧会话事件，并异步关闭端口。

## MCU 自动推断

右侧「MCU 识别」面板始终显示，无需开启开关。每次串口收到 RX 数据时，自动匹配型号标记和已知启动特征；支持 ESP32 / ESP8266、STM32、GD32、CH32、Nordic nRF、RP2040 / RP2350、AVR ATmega / ATtiny、Microchip SAM / PIC、NXP LPC 的常见型号写法。ESP32 ROM 横幅中的 `esp32s3-20210327`、`esp32c3-api1-20210207` 等写法会归一化为型号；部分 Espressif ROM 日期横幅仅作为弱启动线索。

- 展示型号或系列、厂商、已知内核及来自 RX 的匹配依据；未知内核不猜测，不推算 Flash / RAM 容量。
- 型号标记、系列标记、启动特征和 USB 线索分级显示，**所有结果都是推断，不是硬件认证**。输出可能提到外接模块或其他 MCU；遇到多个不兼容候选时列出候选并提示冲突，不强行选择一个。
- 普通 `OK`、AT 版本、RTOS 名称、串口桥型号或无特征二进制数据不足以识别 MCU，会显示「尚未识别」。不自动发送 AT / Bootloader 命令，不改变波特率、DTR / RTS，也不连接网络。
- 支持型号和 ANSI 转义跨 Read 分片；ANSI 颜色及 OSC 控制字符串不会作为型号证据。推断不修改原始字节、消息分组或导出内容。
- 暂停显示、搜索、方向筛选、切换 HEX 和清空日志不会停止推断或清除当前连接的线索。断开或新建连接会重置；演示模式明确显示「演示设备」，回环内容不参与硬件识别。
- 识别状态独立于显示日志并有固定容量：最多保留 16 项不同型号线索，超限后显示提示；候选属于当前连接，不跨重启保存。
- 右侧面板独立滚动；小窗口保留三栏，工作台工具栏自适应换行，收发与识别同时可用。

### 首次发送与物理回环

每次连接的首次有效用户发送（含循环发送的第一条）会启动一次原始字节比对，覆盖实际编码和行尾。仅在驱动确认完整写入、随后 RX 完整匹配时显示「疑似物理回环」。支持任意二进制数据、跨读取分片及 RX/TX 事件通知乱序；不要求固定探测字符串。等待时间按波特率与数据长度计算，最低约三秒；超时或不一致则显示未完整匹配，不会把后续发送当作首次发送重新测试。

物理 TX/RX 短接与固件软件回显在字节层面可能完全一致，因此不显示为确定的物理连接结论。匹配的回显字节不会作为 MCU 型号证据，避免用户发送 `STM32F103C8T6` 后被回环数据误识别；不匹配或超时则恢复分析暂存前缀，原始日志、计数和 CSV 始终不变。演示设备不参与物理回环推断。

### 原生 USB CDC 辅助识别

- Windows 通过系统设备列表、驱动服务 / CDC 兼容 ID 确认接口；Linux 通过 sysfs 的 `cdc_acm` 驱动确认。只有 CDC 且未匹配已知桥接器 / 调试器时，MCU 面板下方才出现「USB 信息」。其他平台暂不提供 USB 辅助识别，RX 推断照常工作。
- CH340/CH341、CP210x、FTDI、PL2303、MCP2221、ST-Link、J-Link、DAPLink、Arduino Uno/Mega 的桥接串口，以及已知 ESP USB Bridge / Pico Debug Probe 等，均不显示 USB 区域、不使用其 VID/PID 推断目标 MCU；USB CDC 本身并不保证是 MCU 的原生接口，未知桥接固件仍可能无法区分。
- 显示系统提供的 VID、PID、产品 / 友好名称、序列号和驱动；厂商描述缺失时可显示本地映射厂商。只读取系统缓存，禁用串口枚举库的主动 USB 描述符探测，元数据失败不会阻断串口收发。
- 多厂商规则集中在 `usbMCURules`：包括 ST STM32 VCP、Raspberry Pi Pico SDK / RP MicroPython、Nordic nRF 厂商线索、Arduino Leonardo/Micro、Adafruit Trinket M0、Microchip SAM / PIC、NXP LPC 和 Espressif 内置 USB Serial/JTAG。没有映射的原生 CDC 仍显示 USB 信息，但不凭未知 ID 猜型号。
- 共享 ID 只推断到系列：例如 `303A:1001` 不唯一对应 ESP32 某型号，`0483:5740` 不唯一对应 STM32 某型号，`2E8A:0005` 也不能区分 RP2040 / RP2350。RX 的具体型号可细化 USB 系列线索；不兼容线索同时保留并提示冲突。
- VID/PID 可被固件修改，不能作为硬件认证。规则参考 [USB ID 数据库](https://github.com/usbids/usbids/blob/master/usb.ids)、[Pico SDK CDC 默认 ID](https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/pico_stdio_usb/stdio_usb_descriptors.c)、[MicroPython RP2 默认 ID](https://github.com/micropython/micropython/blob/master/ports/rp2/mpconfigport.h)、[Espressif PID 分配说明](https://github.com/espressif/usb-pids)及 [ESP USB Bridge](https://github.com/espressif/esp-usb-bridge)。

## 数据与边界

- 原始 RX 记录对应一次读操作的分块，显示消息则按所选模式分组，**两者都不保证是协议帧**。UTF-8 预览缓存尚未收齐的字符，收到后续字节后显示，原始字节不变。
- 每次发送含行尾最多 64 KiB；发送队列 16 项，满时显示错误，不无限堆积。
- 日志最多保留最近 2000 条原始记录且原始数据不超过 2 MiB，超限自动淘汰旧记录，并显示淘汰数量；显示合并不扩大原始日志容量。要长期记录请及时导出。
- 暂停显示仍占用相同的日志容量，过旧的暂停记录仍会被淘汰。清空只清除应用日志与计数，不清空串口驱动缓冲区。
- UTF-8 与 HEX 气泡均显示完整消息，不需要打开检视器才能查看尾部。UTF-8 的 Terminal 完整展开并由外层列表滚动；HEX 仍在独立内容区滚动。二进制请使用 HEX 显示。
- RX / TX 统计记录本次清空以来收到的字节 / 驱动确认写入的字节；驱动写入不等于设备确认接收。
- 不支持硬件流控、协议解析、连接失败的持续重试或持续磁盘录制。默认不会自动打开真实端口；只有开启新增端口检测后，拔插才可能触发自动连接。不会记住设备配置。
- 导出采用 UTF-8 BOM CSV，并对可能被表格软件当作公式的设备文本进行转义；HEX 列保留原始内容。

## 结构与验证

- `app.go`：UI 线程模型、会话代际检查、批量事件投递、过滤、容量管理与导出。
- `serial_session.go`：有界异步读写、短写处理、取消、虚拟设备与循环任务。

- `terminal_preview.go`：Terminal 预览缓存、网格测量与受控高度。
- `mcu_detect.go`：有界的被动 MCU 特征识别、跨读取流状态、候选细化与冲突保留。
